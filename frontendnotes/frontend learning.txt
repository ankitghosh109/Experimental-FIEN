something new a learned about in these dayes: 
React Render + Commit Cycle (Simplified)

Step-1.Render Phase
React calls your function component.
JSX gets converted into a "virtual DOM tree".
No actual DOM mutations happen yet.

Step-2.Commit Phase
React applies DOM updates (in the real DOM).
Browser will eventually paint the screen.
After commit → React runs lifecycle hooks (useLayoutEffect first, then useEffect).

paint means everything is done but Browser not Converted real dom into pixels

difference between useLayoutEffect and useEffect
useLayoutEffect: is synchronous means it will run like Render Phase > React applies DOM updates (in the real DOM) but Browser is not painted yet> it will run then Browser painted the Dom
useEffect: is asynchronous means Render Phase > Commit Phase > Browser painted the Dom > then it will run

means useLayoutEffect alwayes runs before useEffect cuz it is synchronous

you can fetch data without a axios instance but if you create a axiosinstance and use that for fetching this will help you a lot: 
you can config this so you dont have to add all default option in every fetch,
it gives you a option where you can give a baseUrl so you dont have to write it every time,
it gives you a option of headers where you can put your default headers so you dont have to attach it to every fetch request, 
it has a property of interceptor where you can give a callback it will run before any request sent and before reciving the responce and is a centeralize place where all the error come in second callback you give,
you can use this instance to use any fetch method like axiosInstance.post("/route" , data), 
better error handling if you send a request using normal fetch() and server gives 404 500 this will not give error but axios will give you error,
axios has cleanre syntax you code will look clean,
axios dont use fetch() behind the scene it uses xhr and xhr has its own features.
